# LLM Routing: Qwen first, rotating free fallbacks, local model last

## Why providers, not just models
OpenRouter's free cap is **account-wide across every `:free` model** (20 requests/min; 50/day, or 1,000/day after
a one-time $10 credit purchase). Switching from one OpenRouter free model to another does **not** bring back a
used-up daily quota; it only helps when one model is busy upstream. So the chain has three layers:

| Layer | Tiers (default) | What it protects against |
|---|---|---|
| 1. Primary | `qwen/qwen3-coder:free` | Normal operation |
| 2. Same-account alternates | Nemotron 3 Ultra, gpt-oss-120b, Laguna S 2.1, `openrouter/free` (all `:free`) | One model saturated/down upstream, per-minute 429s |
| 3. Other providers (separate quotas) | Google AI Studio, Groq, Cerebras (any with a key) | OpenRouter's daily cap running out |
| 4. Final | Local Ollama (`qwen2.5-coder:3b` default) | Everything hosted exhausted. Unlimited and free, but only as good as your hardware |

Tiers without an API key are skipped silently. You can run with only an OpenRouter key and still get layers 1, 2, 4.

## Per-tier state machine

```text
AVAILABLE ──429 (per-minute / Retry-After)──> COOLDOWN(until retry-after or 60s) ──expires──> AVAILABLE
AVAILABLE ──daily quota hit (429 text, remaining=0, or own counter ≥ rpd)──> EXHAUSTED(until reset 00:00 UTC) ──reset──> AVAILABLE
AVAILABLE ──3× consecutive 5xx/timeout──> CIRCUIT_OPEN(15 min) ──probe ok──> AVAILABLE
any ──404/model removed──> DISABLED (shown in status; fix config)
```
- `quotaScope: provider`: EXHAUSTED applies to **all** tiers of that provider (OpenRouter), so the router doesn't burn
  requests retrying siblings that share the same cap.
- `quotaScope: model`: each model tracked separately.
- State lives in memory plus a small `llm_tier_state` table so a restart doesn't forget an exhausted day.

## Selection algorithm (per LLM call)

```text
for tier in chain order:
    skip if: no key | state ≠ AVAILABLE | context too small | missing capability (json/tools) | local_only and tier hosted
    wait for local token bucket (rpm) if needed (max 2 s), else skip
    call tier
      success + valid output  -> return, record {tier, model, attempts}
      429 / quota             -> mark COOLDOWN or EXHAUSTED, continue to next tier immediately
      5xx / timeout           -> count failure (circuit breaker), continue
      invalid JSON/schema     -> soft-fail, continue to next tier   (policy.softFailToNextTier)
stop after maxAttemptsPerRequest; if nothing worked -> LLM_ALL_TIERS_EXHAUSTED
    (message lists each tier's state and next reset time)
```
Because the loop always restarts from the top for each new call, the router **returns to Qwen on its own** as soon as
its cooldown or daily reset passes. There is no sticky "stuck on the fallback" state.

## Quality guard: JSON must be valid
Condition nodes depend on structured output. A smaller or different model may return broken JSON, so for
`outputFormat: "json"` the router validates against `jsonShape`; failure moves to the next tier. On the local tier it uses
Ollama's `format` (JSON schema) to constrain output.

## Transparency
Different models answer differently, and conditions branch on those answers, so the model used is always recorded:
- `llm` output includes `{ model, tier, provider, attempts: [{tier, result}] }`.
- SSE event `llm.failover` (`from`, `to`, `reason`); the UI shows a badge on the node and a warning when the answer came from the local tier.
- `GET /api/llm/status` returns every tier's state, estimated remaining daily requests, and next reset.
- `routing: "local_only"` on an `llm` node keeps that prompt on your machine (use for anything private, since free hosted endpoints may log prompts).

## Choosing the order (be skeptical of any "best model" list)
The default order is by capability (structured output, tool calling, long context) and current popularity on OpenRouter's
free list, not by a benchmark of workflow design. Free catalogs change monthly: models appear, get renamed, or turn paid.
Plan:
1. **Catalog check at startup** (P1): call `GET /api/v1/models`, confirm each configured `:free` ID still exists and still supports the needed parameters; mark DISABLED otherwise.
2. **Eval harness** (P1): run ~10 golden prompts ("fetch API, summarize, branch on X") through each tier, score by *validator pass rate* then latency, and reorder `tiers:` in the YAML by the results.
3. Re-run the eval whenever a tier is added or a model changes.

## Local final tier: what to expect
- Needs `docker compose --profile local-llm up -d` and `ollama pull <model>`; if unreachable, the tier is skipped.
- Integrated-graphics laptops run it on CPU: use a 3B model (7B only with ~16 GB RAM). Expect slow responses and weaker
  workflow generation, so the AI Builder shows "generated by local model, review carefully".
- Hard-coded `contextTokens: 8192`: the LLM node truncates `{{refs}}` to fit (`maxInputChars`) and tells you it did.

## Adding another provider
Any OpenAI-compatible endpoint: add a `providers:` entry (baseUrl, apiKey env var, quotaScope, limits) and a `tiers:` line.
No code changes.

## Terms and privacy
Free tiers have usage terms and some free models log prompts/completions for the provider's training. Read each provider's
terms before sending real data; use `local_only` for sensitive prompts.
